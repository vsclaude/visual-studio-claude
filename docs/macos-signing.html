Sign & notarize Vey Studio cho macOS trên GitHub Actions

Từ lúc có Apple Developer Program đến lúc CI ra được file .dmg đã ký và đã notarize. Các bước tạo chứng chỉ làm trên Windows bằng Git Bash, không cần máy Mac.

1. Tổng quan

Một bản app macOS phát hành ngoài App Store cần hai thứ để Gatekeeper cho mở mà không chặn:

  • Sign bằng chứng chỉ Developer ID Application, có bật hardened runtime.
  • Notarize: gửi app cho Apple quét. Apple trả về một "vé", được gắn (staple) vào app.

electron-builder làm cả hai nếu có đủ chứng chỉ và thông tin đăng nhập. Việc của mình là tạo ra chúng rồi đưa lên GitHub dưới dạng secret.

2. Tạo private key và CSR

Mở Git Bash (có sẵn khi cài Git for Windows) và làm trong một thư mục nằm ngoài repo, để không lỡ commit private key. 

mkdir -p ~/apple-signing && cd ~/apple-signing
MSYS_NO_PATHCONV=1 openssl req -new -newkey rsa:2048 -nodes \
  -keyout devid.key -out devid.csr \
  -subj "/emailAddress=<email-apple-id>/CN=Vey Studio/C=VN"
Bắt buộc có MSYS_NO_PATHCONV=1. Thiếu nó, Git Bash tưởng chuỗi /emailAddress=… là đường dẫn và đổi thành C:/Program Files/Git/…, làm CSR bị sai.

Kết quả là hai file: devid.csr để upload lên Apple, và devid.key là private key. Giữ kỹ devid.key: mất nó thì phải tạo lại chứng chỉ từ đầu.

3. Tạo chứng chỉ Developer ID Application

  1. Vào developer.apple.com › Certificates và bấm +.
  2. Chọn Developer ID Application, không chọn "Apple Development" hay "Developer ID Installer".
  3. Nếu trang hỏi Profile Type, chọn G2 Sub-CA.
  4. Upload devid.csr, bấm Continue rồi Download, sẽ được file developerID_application.cer.
  5. Chép file .cer vào ~/apple-signing.

4. Ghép thành file .p12

cd ~/apple-signing
openssl x509 -inform DER -in developerID_application.cer -out devid.pem
openssl pkcs12 -export -legacy -inkey devid.key -in devid.pem -out devid.p12
base64 -w0 devid.p12 > devid.p12.b64
  • Lệnh pkcs12 sẽ hỏi mật khẩu export. Đặt một mật khẩu mạnh và ghi lại, nó sẽ thành secret MAC_CSC_KEY_PASSWORD.
  • Cần -legacy vì keychain của macOS không đọc được định dạng p12 mặc định của OpenSSL 3.

Kiểm tra lại:

openssl x509 -in devid.pem -noout -subject

Kết quả phải có Developer ID Application: <tên> (<TEAM_ID>).

5. Chuẩn bị thông tin notarize

Có hai cách. Repo này dùng Apple ID + app-specific password, vì App Store Connect của team chưa có mục API key (Integrations).

Thông tin Lấy ở đâu
Apple ID Email đăng nhập developer.apple.com. Xem tại account.apple.com › Sign-In and Security.
App-specific password account.apple.com › Sign-In and Security › App-Specific Passwords › tạo mới, đặt nhãn ví dụ vey-notarize. Giá trị cần lưu là chuỗi xxxx-xxxx-xxxx-xxxx Apple hiện ra (chỉ hiện một lần), không phải cái nhãn.
Team ID developer.apple.com/account › Membership details. Đó cũng là 10 ký tự trong ngoặc ở dòng Developer ID Application: … (XXXXXXXXXX).
Cách còn lại là dùng App Store Connect API key (Users and Access › Integrations › Team Keys). Lần đầu, Account Holder phải bấm Request Access thì mục này mới hiện. Nếu sau này chuyển sang API key, workflow phải đổi sang các biến APPLE_API_KEY / APPLE_API_KEY_ID / APPLE_API_ISSUER.

6. Tạo secret trên GitHub

Vào repo › Settings › Secrets and variables › Actions › New repository secret. Mỗi secret: nhập Name, dán giá trị vào ô Secret rồi bấm Add secret.

Name Giá trị Dùng để
MAC_CSC_LINK Toàn bộ nội dung devid.p12.b64 sign
MAC_CSC_KEY_PASSWORD Mật khẩu export ở bước 4 sign
APPLE_ID Email Apple ID notarize
APPLE_APP_SPECIFIC_PASSWORD Chuỗi xxxx-xxxx-xxxx-xxxx notarize
APPLE_TEAM_ID Team ID 10 ký tự notarize

Chuỗi base64 rất dài, đừng gõ tay. Copy vào clipboard trong Git Bash bằng lệnh: 

cat ~/apple-signing/devid.p12.b64 | clip

Khi dán, đừng để thừa dấu cách hay xuống dòng ở cuối. RELEASES_TOKEN (để publish release) đã có từ trước, không liên quan đến việc sign.

CSC_IDENTITY_AUTO_DISCOVERY không phải secret. Workflow tự đặt nó thành true sau khi import chứng chỉ thành công.

7. Cấu hình trong repo

resources/entitlements.mac.plist

Notarize đòi hardened runtime, và khi bật nó thì Electron cần thêm quyền:

  • com.apple.security.cs.allow-jit và allow-unsigned-executable-memory: không có thì V8 không chạy được. Daemon và tsserver là chính binary này chạy với ELECTRON_RUN_AS_NODE, nên cũng nhận các quyền này.
  • com.apple.security.cs.disable-library-validation: để nạp module native của node-pty và typescript riêng của từng project.

package.json › build.mac

"hardenedRuntime": true,
"entitlements": "resources/entitlements.mac.plist",
"entitlementsInherit": "resources/entitlements.mac.plist"

Không đặt "notarize": false. electron-builder tự notarize khi thấy APPLE_ID / APPLE_APP_SPECIFIC_PASSWORD / APPLE_TEAM_ID, thiếu thì bỏ qua và chỉ cảnh báo.

.github/workflows/release.yml

Job macOS có hai bước:

  1. Import the Developer ID certificate: giải mã MAC_CSC_LINK, tạo một keychain riêng với mật khẩu ngẫu nhiên, import .p12, chạy set-key-partition-list, thêm keychain vào danh sách tìm kiếm, in identity ra log, rồi ghi MAC_SIGNING=true. Không có secret thì bước này bỏ qua và job build bản không ký.
  2. Build installers: CSC_IDENTITY_AUTO_DISCOVERY=${{ env.MAC_SIGNING == 'true' }} cùng ba biến APPLE_*, rồi chạy electron-builder --mac.

Chứng chỉ được tự import thay vì truyền qua CSC_LINK, vì keychain tạm của electron-builder bị lỗi trên runner (xem mục 9). Cách này cũng tránh được việc electron-builder dùng CSC_LINK để ký Windows bằng một chứng chỉ không phải Authenticode. Windows và Linux vẫn không ký.

8. Chạy và kiểm tra

  1. Commit, rồi git push.
  2. Vào Actions › Release › Run workflow và chọn branch. Lần chạy tay chỉ build, không publish. Publish thật chỉ chạy khi push tag v*.
  3. Xem log job package (macos):

Bước import: 1 valid identities found và Developer ID Application: … (TEAM_ID)

Bước build: signing … identityName=Developer ID Application: …, sau đó là notarization successful (thường mất 2–10 phút)

Kiểm tra trên một máy Mac, sau khi tải .dmg từ artifact và cài app: 

codesign --verify --deep --strict --verbose=2 "/Applications/Vey Studio.app"
spctl --assess --type execute --verbose "/Applications/Vey Studio.app"
xcrun stapler validate "/Applications/Vey Studio.app"

spctl phải báo accepted và source=Notarized Developer ID.

9. Lỗi thường gặp

Lỗi Nguyên nhân và cách xử lý
set-key-partition-list … SecKeychainUnlock: The user name or passphrase you entered is not correct Lỗi ở keychain tạm của electron-builder khi truyền chứng chỉ qua CSC_LINK. Cách xử lý là tự import chứng chỉ vào keychain riêng trong một bước trước, như workflow hiện tại.
security import báo MAC verification failed MAC_CSC_KEY_PASSWORD không khớp với file .p12, hoặc MAC_CSC_LINK bị dán thiếu hay thừa ký tự. Copy lại bằng clip.
0 valid identities found Chứng chỉ không khớp với private key (ví dụ ghép nhầm một devid.key khác), hoặc chọn sai loại chứng chỉ ở bước 3.
Notarize báo sai thông tin đăng nhập Đã lưu cái nhãn thay vì chuỗi mật khẩu, hoặc mật khẩu được tạo từ một Apple ID khác với APPLE_ID, hoặc sai APPLE_TEAM_ID.
Notarize trả về Invalid Xem log chi tiết bằng xcrun notarytool log <submission-id>. Thường là có binary chưa được ký, hoặc thiếu hardened runtime.
App mở ra crash ngay sau khi sign Thiếu entitlements (xem mục 7). Kiểm tra bằng codesign -d --entitlements - "/Applications/Vey Studio.app".

10. Sau khi xong

  • Cất devid.key, devid.p12 và mật khẩu export vào trình quản lý mật khẩu, rồi xoá các bản trong ~/apple-signing.
  • Không bao giờ dán secret vào chat, issue hay commit. Lỡ lộ thì thu hồi app-specific password và tạo mật khẩu mới, rồi bấm Update secret trên GitHub.
  • Chứng chỉ Developer ID có hạn khoảng 5 năm. Khi gia hạn thì làm lại từ bước 2 và cập nhật MAC_CSC_LINK và MAC_CSC_KEY_PASSWORD.
  • Khi app đã được ký, các chỗ trong repo còn ghi là bản build "unsigned" nên được cập nhật: README, cảnh báo quarantine trong install.sh, updater.ts, docs/design.md § Updating.
